# Alpha MVP7.8.4 Gate DAG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the accepted Option A `DB_FIRST_API_LAST` DAG with structured current checkpoint evidence, independent DB branches and terminal non-authoritative smoke consolidation.

**Architecture:** A pure gate module normalizes sanitized executor results into context-bound evidence and validates the exact three-gate API bundle. Existing dormant executors expose only the additional sanitized validation metadata needed by that module, while a separate pure consolidator creates terminal BASIC/FULL summaries after the API.

**Tech Stack:** Python 3, pytest, argparse, existing fake Oracle/HTTP doubles, Markdown contracts; no new dependency.

**Spec:** `docs/superpowers/specs/2026-08-22-alpha-mvp784-gate-dag-design.md`

## Global Constraints

- `TASK_CLASS=DEVELOPMENT`.
- Canonical dependency order is `ACM_CUSTOM | ACM | BDA -> API -> Manager consolidation`; DB scheduling order is not dependency.
- `BASIC_DB_CHECKPOINT_OK` is not a canonical node, producer, aggregate or admission condition.
- API accepts exactly `ACM_CUSTOM_DB_CHECKPOINT_OK`, `ACM_DB_CHECKPOINT_OK` and `BDA_DB_CHECKPOINT_OK` as structured current evidence.
- `smartoffers_basic_smoke` resource membership remains unchanged; the three-DB API node uses `smartoffers_qa4_full_smoke`.
- One attempt, zero retry, finite limits, read-only checks, no fallback, no alternate credential and no sensitive logging remain mandatory.
- Do not change `safe_for_real_execution`, catalog `execution_status`, `mode=real`, Flask routes or JSON scenario compatibility.
- Tests use only fake clients/drivers and perform no Oracle, HTTP, Kafka, Jenkins, FTM, DNS, socket, subprocess, production or mutation activity.
- `CONTRACT_CONFLICT-001` is closed only after independent Tester acceptance.
